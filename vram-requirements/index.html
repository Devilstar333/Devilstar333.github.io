VRAM guide

How much VRAM does a local LLM need?

The size of the downloaded file is not what your machine must hold in memory while the model runs. Three costs add up: the weights, the runtime/compute buffers, and the KV cache — which grows with the context length and is the number one cause of out-of-memory errors after the weights.

The tables below use the same formula as the interactive calculator, assuming a 0.75 GB display reserve, a 2.5 GB OS/app reserve and an 8k context. Values are the total memory needed, in GB.

The formula (no guessing)

weights   = parameters (billions) × effective bits ÷ 8
overhead  = 20% of weights + 0.6 GB    (runtime + compute buffers)
KV cache  ≈ 0.007 GB × parameters (B) × (context ÷ 1024)
total     = weights + overhead + KV cache

Effective bits per weight: Q4_K_M ≈ 4.5 · Q6_K ≈ 6.5 · Q8_0 ≈ 8.5 · FP16 = 16. Models with grouped-query attention (GQA) have smaller KV caches; doubling the context roughly doubles that term.

Frequently asked questions

How much VRAM does a 32B model need at Q4?

About 24 GB with an 8k context, including weights, runtime overhead and KV cache. A 24 GB card is borderline (the display reserve eats into it); 32 GB is comfortable.

Does a 70B model fit in 48 GB of VRAM?

No. At Q4_K_M a 70B model needs roughly 52 GB with an 8k context, so about 64 GB of VRAM to run entirely on the GPU. With 48 GB you will be offloading part of it — or running it on a rented cloud GPU instead.

Why is more memory needed than the model file size?

Three extra costs: runtime and compute buffers (~0.6 GB, fixed), roughly 20% overhead on the weights, and the KV cache, which grows with the context length. A 13.5 GB file can easily need 18 GB at runtime.

What happens if the model does not fit in VRAM?

llama.cpp and clients such as LM Studio and Ollama offload layers to system RAM. It still runs, but generation speed drops several times, because DDR5 bandwidth (~80 GB/s) is far below GPU bandwidth. Reduce the context, use a lower quantization, or pick a smaller model.

Is Q4_K_M good enough?

It is the sweet spot most people run: quality close to the original for chat and coding, at roughly a quarter of the FP16 memory. Move up to Q6_K or Q8_0 only when you have memory to spare.

How much does the context length matter?

The KV cache term is roughly proportional to the context: going from 8k to 32k turns a 1.3 GB cache into about 5.4 GB on a 24B model. That is often the difference between fitting and not fitting.
